# Flow — цифровой штаб строительства

Размещение: **dsflow.ru**. Версия: `2026.10.09-flow.2`. Архитектура и роли — [ARCHITECTURE.md](ARCHITECTURE.md).

- `/` — реальные объекты (БЦ «Огни», БЦ «Раменки») на едином рабочем столе Flow; вход — основной пароль стартового экрана.
- `/demo/` — демо-режим (кнопка «Демо-режим» внизу слева на стартовом экране): вымышленные объекты, вход под ролью
  `admin`, `director`, `tech`, `smeta`, `gip`, `investor`, `contractor1…contractor38` (начальный пароль `1234`).
- `/ogni/work.html`, `/ramenki/work.html` — рабочие модули объектов (ввод факта, «Обновление данных», бюджет и КС, фото).
  Прежние адреса `/ogni/`, `/ramenki/` открывают объект во Flow.
- `api/` — Flow API (FastAPI): вход, реальные проекты, демо-контур с серверной проверкой прав.

## Размещение (GitHub → Timeweb App Platform)

**Frontend** (как и раньше): приложение HTML/CSS/JS, директория проекта `public`, сборка не нужна.

**Backend** (как и раньше): Backend → Python → FastAPI, директория `api`, сборка `pip3 install --upgrade -r requirements.txt`,
запуск `python3 main.py`, healthcheck `/health`. Адрес API для сайта задаётся в одном месте — `public/flow/env.js`
(сейчас `https://dailybuildreport-dsflow-9ab6.twc1.net`; если API будет на другом адресе — поменять там).

Новые переменные окружения API:

| Переменная | Назначение |
|---|---|
| `FLOW_SECRET` | **обязательно задать** — ключ подписи токенов (длинная случайная строка). Без неё сессии сбрасываются при перезапуске |
| `REAL_PASSWORD_SHA256` | необязательно: sha256(`dsflow.v1:` + основной пароль). По умолчанию — хэш текущего пароля, вход не меняется |
| `FLOW_DEMO_STORAGE` | `file` (по умолчанию, каталог `FLOW_DATA_DIR`, `./var/demo`) или `postgres` |
| `FLOW_DATA_DIR` | каталог демо-хранилища для `file` |
| `FLOW_TOKEN_TTL` | срок сессии, секунд (по умолчанию 43200) |
| `CORS_ORIGINS` | как и раньше: `https://dsflow.ru,https://www.dsflow.ru` |
| `FLOW_FILE_TYPES` | допустимые форматы документов (по умолчанию `pdf,dwg,docx,xlsx,jpg,jpeg,png`) |
| `FLOW_FILE_MAX_MB` | максимальный размер файла, МБ (по умолчанию 25) |
| `FLOW_AI_URL` | адрес ИИ-сервиса проверки документов; без него ИИ-проверка не выполняется (503) |

**Миграции БД.** Существующие таблицы не меняются. Для `FLOW_DEMO_STORAGE=postgres` выполнить один раз
`api/migrations/001_flow_demo.sql` и `002_flow_accounts.sql` (таблицы `flow_demo_contractors`, `flow_demo_journal`,
`flow_demo_kv` — пользователи, роли, журнал безопасности; только демо-данные).
При `file` миграции не нужны; демо возвращается к исходному состоянию при очистке каталога или новом деплое.

**Порядок выката:** сначала API (с `FLOW_SECRET`), затем frontend. Если frontend окажется раньше API, основной вход
продолжит работать (резервная проверка по хэшу), не откроется только демо-режим.

## Проверка

- API: `cd api && pip install -r requirements-dev.txt && pytest -q` — 20 тестов: роли и учётные записи, 403 на чужой
  объект, разделение контуров, маршрут корректировки, КС-2 и отчёты, база подрядчиков, пароли (завершение сессий,
  журнал без пароля), роли и матрица прав, сметчик и ГИП, отсутствие сброса, доступ к файлам документов, проверка
  документов и ИИ, маршрут сметы, права на договоры и график, обязательные поля замечания.
- Сроки: `node tools/qa/cpm-scenarios.js` — 10 сценариев CPM и анализа влияния + проверка сетей демо-объектов.
- Телефон: `python3 tools/qa/ui-mobile.py` (нужны запущенные API и статический сервер) — горизонтальная прокрутка,
  нижняя навигация, блокировка прокрутки под окнами, ошибки JavaScript для всех ролей.
- Локально: `cd api && FLOW_SECRET=x CORS_ORIGINS=http://127.0.0.1:8765 python3 main.py`, затем
  `python3 -m http.server 8765 --directory public` и в консоли браузера `localStorage.setItem('flow.api','http://127.0.0.1:8000')`.

## Исходные данные демо

`api/demo_data/src/` — датасеты пяти вымышленных объектов; `python3 tools/make-demo-docs.py` создаёт
демо-документы «Кристалл Парк» (`api/demo_data/files/`), `node tools/export-demo-data.js` собирает JSON для API
(с демо-сметами и реестром документов).
В `public/` демо-данных нет — их выдаёт только сервер с учётом роли.

# Рабочие модули реальных объектов (описание предыдущих выпусков)

## Обновление данных (с dsflow.24)

Принцип: **конкретные виды работ — это данные проекта, а не архитектура.** Работа, веха, договор, риск, событие и фото —
универсальные сущности с параметрами; их состав у каждого проекта свой и меняется без изменения кода.

- Два способа, одна модель: ручная форма и стандартный Excel-файл дают одинаковый набор входящих данных,
  который проходит одну проверку «Было → Стало» и применяется в единую модель проекта.
- Период: день, неделя (базовый сценарий), месяц или произвольный.
- Excel-шаблон: `assets/templates/dsflow-update-template.xlsx` (пустой) или «Шаблон с данными проекта» из DSFlow
  (все работы, вехи, договоры, риски с их ID). Листы: Инструкция, Паспорт обновления, Готовность проекта, Работы, Вехи,
  Бюджет, Договоры, Риски, События, Фото, Итог периода. Пустая ячейка — не менять, «-» — очистить, серые столбцы — расчёт DSFlow.
- Загрузка: DSFlow определяет проект (код в паспорте) и период, читает все листы, сопоставляет строки по ID
  (без ID — по точному названию), показывает «Новая сущность», «Изменено», «Изменён статус»,
  «Не удалось однозначно сопоставить» (решает пользователь) и применяет только после подтверждения.
- Куда пишется: работы — слой правок графика (`S.admin`) и журнал факта (`S.records`, новые записи на дату актуальности,
  прошлое не перезаписывается); договоры — `S.budget`; вехи, риски, события, показатели бюджета, заявленная готовность,
  итоги периодов и история — `S.upd`. После применения `build()` пересчитывает проект, и обзор, готовность, Гант,
  календарь, бюджет, фотохроника и остальные разделы читают один граф `M`.
- История: период, дата, пользователь, источник, исходный файл (хранится в браузере), старое и новое значение каждого поля.
- Производные показатели (проценты, отклонения, просрочка, остатки, прогноз) считает DSFlow; % выполнения — из объёмов, если они указаны.
- Файлы: `assets/dsflow-update.js` (форма, проверка, применение, история), `assets/dsflow-update-xlsx.js`
  (структура файла, сборка и чтение — общий для браузера и `tools/build-update-template.js`), `assets/vendor/exceljs.min.js` (MIT).
- Пустой шаблон пересобирается: `npm i exceljs@4.4.0 && node tools/build-update-template.js`.

## Бюджет: договоры, сметы, КС-2, КС-3 (с dsflow.21)

Изменение бюджета доступно только в режиме администрирования (⚙ внизу меню → «Бюджет и договоры»): там кнопка «+» добавляет договор; на странице договора — сметы, акты КС-2 и справки КС-3 (добавление, изменение, удаление с подтверждением). Акты КС-2 увеличивают закрытие по договору и закрытие по месяцам, оплаты по КС-3 — «Оплачено». Данные хранятся в браузере (`<префикс>budget`), в среде Claude — в общей базе проекта; исходные договоры объекта не меняются. План закрытия для новых договоров не задаётся и показывается как «—». Обычный пользователь видит бюджет, договоры и документы только для просмотра; финансовые предложения ИИ применяются только в режиме администрирования.

## Вход в систему (временная авторизация, с dsflow.20)

- `public/login.html` — экран входа. `public/assets/dsflow-auth.js` — единый модуль авторизации и охраны страниц; подключён первым скриптом в `<head>` страниц `index.html`, `ogni/index.html`, `ramenki/index.html`, `ogni/report.html`.
- Без активной сессии любая защищённая страница переходит на `login.html?next=<исходный адрес>`; после входа пользователь возвращается туда. Экран входа не охраняется и в цикл не попадает.
- Сессия хранится в `sessionStorage` (`dsflow.session`) и сбрасывается при закрытии браузера. Кнопка «Выйти» есть в шапке экрана выбора проектов и в меню переключения объекта; любой элемент с атрибутом `data-dsf-logout` работает так же (`DSFlowAuth.logout()`).
- Пароль в файлах не хранится — только SHA-256 с солью. Это временная защита интерфейса статического сайта, а не защита данных: файлы в `public/` остаются доступны по прямым адресам.
- Переход на backend + PostgreSQL: заменить объект `provider` в `dsflow-auth.js` на запрос к серверу (пример в комментарии). Экран входа, охрана страниц, возврат на исходный адрес и выход не меняются. Для защиты данных сервер должен сам проверять сессию при выдаче страниц и данных.
- Service worker кэширует страницы, но проверка сессии выполняется в самой странице, поэтому открытие закэшированной страницы (в том числе офлайн) тоже ведёт на экран входа.

## Открыть на компьютере

Сайт находится в папке `public`. Для полной проверки нужен локальный веб-сервер; открытие HTML двойным щелчком не включает PWA.

Если установлен Python 3, из папки этого пакета выполните:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory public
```

Откройте [DSFlow](http://127.0.0.1:8765/). После первого открытия с доступной сетью сайт сохраняет главную, оба проекта и необходимые ресурсы для автономной работы. Для установки приложения на опубликованном сайте нужен HTTPS.

1. Распакуйте архив. В корне репозитория `dailybuildreport/dsflow` должны оказаться `README.md`, `CHECKS.md`, `THIRD_PARTY.md`, `.gitignore` и папка `public`. Загружайте содержимое папки `dsflow`, а не сам ZIP и не дополнительную внешнюю папку.
2. В Timeweb App Platform выберите frontend-приложение **HTML/CSS/JS**, этот репозиторий и ветку с файлами.
3. Укажите **директорию проекта `public`**. Команда сборки и установка зависимостей для этого формата не требуются: пакет уже содержит готовый сайт. Основание: [официальная инструкция Timeweb](https://timeweb.cloud/docs/apps/deploying-frontend-apps/static-website).
4. Сначала проверьте главную и оба проекта на техническом адресе приложения. Затем привяжите купленный домен `dsflow.ru` по настройкам, которые покажет Timeweb, и проверьте HTTPS.

## Данные и возможности текущей версии

«Огни» используют сводки, встроенные в исходный HTML. Их ежедневные расчёты, история и графики сохранены. Новые подтверждённые записи добавляются поверх исходной истории через интерфейс ввода и сохраняются в хранилище текущего браузера. Файлы отчётов разбираются локально, а предлагаемые ИИ изменения требуют проверки и подтверждения пользователя. Между устройствами эти записи пока не синхронизируются; очистка данных сайта удалит локальные изменения.

«Раменки» сохраняют подтверждённые изменения факта и настройки в хранилище текущего браузера с исходным префиксом `rmk.`. Между сотрудниками и устройствами они пока не синхронизируются. Данные с прежнего адреса автоматически на `dsflow.ru` не переходят; перенос нужно организовать отдельно. Очистка данных сайта удалит локальные изменения.

Встроенные фотографии «Раменок» остаются в HTML. Переданные изображения на карточках проектов — архитектурные рендеры, а не снимки текущей стройплощадки. Фотографии хода работ «Огней» пока не переданы. Загруженные через новый раздел снимки «Огней» сохраняются в IndexedDB текущего браузера; общий доступ к ним с других устройств потребует серверного хранилища. В исходном приложении «Раменок» загрузки в обычном браузере живут в памяти страницы и теряются после перезагрузки или ухода в другой проект.

Для анализа отчётов ИИ используется существующий режим Claude (`window.claude`). На обычном опубликованном сайте без этой среды функция ИИ недоступна; ручной ввод «Огней» и исходные возможности «Раменок» остаются доступными. У DSFlow пока нет общего серверного API, базы данных и синхронизации. Ключей API в пакете нет.

Вход пользователей и разграничение доступа пока не реализованы. Частный репозиторий GitHub сам по себе не ограничивает доступ к размещённому сайту; перед использованием как общего рабочего портала нужен отдельный этап настройки доступа и общей базы.

## Обновлять сайт

При каждом изменении HTML, стилей, скриптов или ресурсов повышайте `VERSION` в `public/sw.js` и значение `app-version` в четырёх HTML (главная, `ogni/index.html`, `ogni/report.html`, `ramenki/index.html`). Для обновляемых CSS/JS/JSON синхронно меняйте параметр `?v=` в ссылках HTML/JS и списке `CORE` в `sw.js`. При добавлении нового ресурса для автономной работы включайте его путь в `CORE`.

После публикации откройте сайт при доступной сети и проверьте обновление. Общий worker не перезагружает открытую форму при активации. Существующая проверка версии «Огней» сохранена.

Результаты проверки и участие Claude описаны в [CHECKS.md](CHECKS.md), сторонние библиотеки — в [THIRD_PARTY.md](THIRD_PARTY.md).
